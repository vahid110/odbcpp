# ODBCPP bounded task

Read `AGENTS.md`, the compact current private handoff and
[DEVELOPMENT_WORKFLOW.md](../../../DEVELOPMENT_WORKFLOW.md). The human's current
scope and holds take precedence. Workflow readiness does not resume product work.

1. Inspect actual baseline, worktrees, local changes, running processes and space.
   Preserve dirty/history checkouts and original evidence. Select an isolated
   `codex/` branch at the exact chosen head; never assume a historical branch.
2. State problem/completion condition, owned files/contracts and required checks.
   Classify changed SDK/backend/ODBC foundations as required by `AGENTS.md`.
   One coordinator owns resource use and integration. Delegate only worthwhile
   independent implementation under a finite lease, not permanent role lanes.
3. Implement a coherent change and preserve valid assertions. Use focused checks
   and relevant regression; collect a full applicable suite before grouped repairs
   when a full checkpoint is initiated. Use driver logs to distinguish product,
   fixture/input and execution-environment defects. Apply the changed-GTest brace
   check when C++ tests change, plus actual compiler/runtime checks as appropriate.
4. Follow [the command matrix](../../../tools/development/COMMANDS.md). CTest owns
   cases/results; small resource helpers own lifecycle and cleanup. Use local
   interactive Windows GUI execution. Record source/config/image/inventory and
   raw results; never treat an interrupted process or a different binary as a pass.
5. Obtain one substantive independent review of actual diff/results, including
   ownership placement, assertion validity and remaining acceptance debt. Resolve
   findings, then integrate exact reviewed bytes only within current authorization.
   Product PRs still need macOS/Linux/Windows builds; full checkpoint/release gates
   remain. Do not replay full product suites for prose-only edits.
6. Verify owned process/resource/fixture/input cleanup and preserve failure evidence.
   Update one compact handoff with head/task, actual results, debt/blocker and next
   action. Archive superseded context. No automatic continuation, timers, billing
   probes, unrelated work or cloud authority is created by this skill.

Periodic live checkpoints follow the canonical 12-active-hour due-state policy;
no live launch while paused or during workflow replacement. Existing protected
operator/admission/security/runtime/cleanup constraints remain unchanged.
